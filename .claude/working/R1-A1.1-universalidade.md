## 2. Agrupamento por temas + análise de redundância

### Tema A — Planejamento prévio obrigatório
Regras: 25-31, 57-63
**Redundância: ~85%.** `plan-first.md` e `plan-first-workflow.md` são essencialmente o mesmo template aplicado a contextos diferentes (Transcritorio Python vs. mensalizacao_pnad R). Ambos definem planejamento obrigatório, formato de plano, status, distinção trivial/não-trivial.
- Diferença real: `plan-first.md` referencia EnterPlanMode/ExitPlanMode (tools Claude Code); `plan-first-workflow.md` integra protocolo de recuperação de sessão e adiciona "Loop de Investigação".
- **Candidato a fusão.**

### Tema B — Investigação antes de implementar
Regras: 32-42, 51-53
**Redundância: alta**, mas `investigate-before-implement.md` declara "PRIORIDADE: MÁXIMA — prevalece sobre todas as outras regras". `test-first-protocol.md` repete o mesmo loop com pequenas variações.

### Tema C — Mudanças mínimas e cirúrgicas
Regras: 6-16, 43-50
**Redundância: ~95%.** `development-procedure.md` (Python/Qt) e `minimal-changes.md` (R) são literalmente o mesmo template. Mesma estrutura, mesma ordem obrigatória, mesma proteção de funções críticas, mesmos anti-padrões, mesmo checklist.
- **Candidato a fusão imediata.**

### Tema D — Protocolo de testes
Regras: 39, 51, 54-56, 72-79
- `test-first-protocol.md` foca no loop de investigação (R/testthat)
- `testing-protocol.md` detalha hierarquia toy/unit/integração + checklists pré/pós-build (Python/PyInstaller)
- **Redundância parcial (~40%); complementares.**

### Tema E — Recuperação de sessão
Regras: 17, 18-24, 62-63
- `session-recovery.md` é o canônico (verificações de build state, git status/log, hierarquia de fontes)
- Repetido parcialmente em `plan-first-workflow.md` (~30% sobreposição)
- Elementos únicos do `session-recovery.md`: checks de build-venv, dist, CUDA, tamanho — esses são Transcritorio-específicos.

### Tema F — Proteção de dados/originais
Regras: 1-4, 70-71
- `pipeline-safety.md`: estrutura de pipeline (inputs/outputs ASR)
- `protect-originals.md`: integridade de dados de pesquisa original
- Complementares; redundância mínima (~10%).

### Tema G — UI/GUI (DOMÍNIO-ESPECÍFICO)
Regras: 65-69
- `gui-development.md` é 100% específico Transcritorio/PySide6/Qt.
- **Não universal — descartar.**

## 4. Glossário emergente

| Termo | Definição operacional | Divergências | Recomendação |
|---|---|---|---|
| Tarefa trivial | Typo, comentário, atualização de docs `.claude/`, `CLAUDE.md`, `MEMORY.md` | Quase consensual | Usar `plan-first.md`: "1 arquivo, sem lógica" |
| Tarefa não-trivial | 2+ arquivos, feature, bug multi-impacto, função protegida, CRAN submit, vignettes | `plan-first.md` mais simples; `plan-first-workflow.md` mais específico | Consolidar: "2+ arquivos OU feature OU bug multi-impacto OU função protegida" |
| MEMORY.md | Arquivo persistente entre sessões com descobertas, estado de planos | Caminho varia (Transcritorio vs. genérico) | Unificar: "`memory/MEMORY.md` ou auto-memory do projeto" |
| Session recovery | Protocolo após compressão: CLAUDE.md → MEMORY.md → planos → git → confirmar | Aparece em 2 arquivos | Definição única em novo `recuperacao-sessao.md` |
| Ciclo INV-PLAN-TEST | INVESTIGAR (causa raiz) → PLANEJAR (texto) → TESTAR (toy isolado) → CHECKLIST 6 → IMPLEMENTAR | Aparece em 3 arquivos | Definição canônica do `investigate-before-implement.md` |
| Mudança mínima/cirúrgica | Só o necessário; sem refactor oportunista; sem cosmética; testar antes do real | Idêntica em 2 arquivos | Consolidada |
| Funções protegidas | Lista explícita de funções críticas que exigem plano aprovado | Tabelas separadas (Qt vs R) | Manter conceito, listar por tipo de função (não nome) |
| Toy/unit test | Toy: <30s, sintético; Unit: <2min, dados reais; Integração: pipeline completo | `test-first-protocol.md` simpler; `testing-protocol.md` detailed | Hierarquia clara: toy → unit → integração |
| Contexto comprimido | Situação quando Claude resume memória; desencadeia recovery | Sem divergência | OK |
| Hierarquia de fontes | 1.Plano > 2.MEMORY.md > 3.CLAUDE.md > 4.rules > 5.git | Listada em 2 arquivos | `session-recovery.md` como autoridade |

- **~60% dos 11 arquivos é duplicação** do mesmo template aplicado a stacks diferentes.
- **Núcleo inviolável**: ciclo investigação-planejamento-teste aparece 3× com prioridade máxima.
- **5 temas universais emergentes**: Planejamento, Mudanças mínimas, Ciclo de teste, Recuperação de sessão, Proteção de dados.
- **1 arquivo descartável** (`gui-development.md`).
- **11 arquivos podem virar 6** sem perda.
