## Ajustes obrigatórios para Rodada 4

### Skills — frontmatter oficial completo
```yaml
---
name: kebab-name                       # opcional (default = nome do dir)
description: "max 1.536 chars (description + when_to_use combinados)"
when_to_use: "quando Claude deve auto-invocar"
argument-hint: "[arg1] [arg2]"
arguments: ["primeiro", "segundo"]     # space-separated ou YAML list para $name
disable-model-invocation: false        # true = só humano invoca
user-invocable: true                   # false = só Claude invoca
allowed-tools: "Read Grep Bash(python *)"  # space-separated ou YAML list
model: opus|sonnet|haiku               # override modelo
effort: low|medium|high|xhigh|max      # nível de esforço
context: fork                          # executa em subagent isolado
agent: Explore|Plan|general-purpose    # subagent type quando context: fork
hooks: { ... }                         # hooks scoped à skill
paths: ["data/**"]                     # glob patterns que limitam ativação
shell: bash|powershell                 # default bash
---
```

- SKILL.md alvo: < 500 linhas; arquivos auxiliares em `examples/`, `templates/`, `scripts/` na mesma pasta.
- Substitutions: `$ARGUMENTS`, `$0`, `$1`, `$name`, `${CLAUDE_SESSION_ID}`, `${CLAUDE_SKILL_DIR}`.
- `disable-model-invocation: true` recomendado para skills com side effects (`/rodar-pipeline`, `/capturar-norma`).
- Skills com `context: fork` viram subagent isolado — útil para tarefas longas.

### Agents — frontmatter
```yaml
---
name: opcional                         # default = nome do arquivo
description: "o que faz"
---
```

- **Não há** campo `tools` no agent (perms vêm de `.claude/settings.json`).
- **Não há** campo `model` no agent (usa modelo da session).
- Agents NÃO podem chamar outros agents diretamente.
- Agents PODEM usar skills e tools permitidos.
- Agent Teams (Fev 2026) habilita coordenação entre múltiplas sessões — `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` já está no `~/.claude/settings.json` da usuária.

### Hooks — sintaxe oficial settings.json

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/block_xlsx_write.py",
            "timeout": 5
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          { "type": "command", "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/warn_lock_file.py" },
          { "type": "command", "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/validate_json_schema.py" }
        ]
      }
    ]
  }
}
```

- Eventos: `SessionStart`, `UserPromptSubmit`, **`PreToolUse`** (único bloqueante para tools), `PostToolUse`, `PostToolUseFailure`, `Stop`, `SessionEnd`, `PermissionRequest`, `InstructionsLoaded`, `TeammateIdle`/`TaskCreated`/`TaskCompleted` (Agent Teams).
- Matcher: `*` ou omitido = todos; alphanumeric = exact match; com chars especiais = regex (ex.: `^Notebook`); MCP tools: `mcp__server__tool`.
- Hook input via JSON em stdin: `{tool, tool_input: {file_path, ...}, ...}`.
- Hook output: exit 0 = sucesso; **exit 2 = bloqueia** (NÃO exit 1) com stderr mostrado; outros exit codes = não-bloqueante.
- Para PreToolUse bloqueante com mensagem visível, JSON em stdout:
  ```json
  {
    "hookSpecificOutput": {
      "hookEventName": "PreToolUse",
      "permissionDecision": "deny",
      "permissionDecisionReason": "Mensagem ao usuário em PT-BR explicando o bloqueio."
    }
  }
  ```
- Hook handler types: `command` (mais comum), `http`, `mcp_tool`, `prompt`, `agent`.
- Windows: scripts Python OK; bash via WSL/git-bash OK; PowerShell via `shell: powershell`.
- Path absoluto recomendado: `$CLAUDE_PROJECT_DIR/.claude/hooks/<arquivo>.py`.

### Settings.json — campos importantes

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Read(data/**)", "Bash(python scripts/*)", "WebFetch(domain:gov.br)"],
    "deny": ["Edit(*.xlsx)", "Bash(rm -rf *)"],
    "ask": ["Bash(git push *)"],
    "defaultMode": "default",
    "additionalDirectories": ["d:\\tmp"]
  },
  "env": {
    "PYTHONDONTWRITEBYTECODE": "1",
    "PYTHONIOENCODING": "utf-8",
    "PYTHONUNBUFFERED": "1",
    "LANG": "pt_BR.UTF-8"
  },
  "model": "claude-opus-4-7",
  "effortLevel": "high",
  "hooks": { /* ... */ },
  "autoMemoryEnabled": true
}
```

**Sintaxe permissões:**
- `Bash(npm run *)` — começando com "npm run"
- `Read(/src/**)` — recursivo
- `WebFetch(domain:gov.br)` — domínio
- `Edit(/src/**/*.ts)` — gitignore-style
- Espaço importa: `Bash(ls *)` ≠ `Bash(ls*)`

**Hierarquia (precedência alta→baixa):**
1. Managed (org-wide)
2. Local (`.claude/settings.local.json`, gitignored)
3. Project (`.claude/settings.json`, versionado)
4. User (`~/.claude/settings.json`)

### Path-scoped rules (recurso emergente — adotar)

Adicionar `paths: [...]` em frontmatter de rules para carregar SÓ quando contexto incluir esses paths:

```yaml
---
paths:
  - "scripts/**/*.py"
  - "tests/**"
---

# Pipeline Python — boas práticas
- ...
```

- Reduz contexto carregado, melhora foco.
- Regras universais (planejamento, ciclo, recuperação) ficam SEM `paths:` (sempre carregam).
- Regras técnicas (pipeline-python-etl, dados-politicas, captura-responsavel, operacao-drive) têm `paths:` específico.

### Plan Mode obrigatório por path

R3.1 sugere paths que forçam `/plan` antes de edit:
- `data/raw/**` (fonte primária imutável)
- `scripts/etl/*.py` (pipeline crítico)
- `data/derived/**/*.json` (após ETL)

Documentar em `rules/planejamento-obrigatorio.md` com `paths:` explícito.

### Memória — estrutura oficial

- `.claude/CLAUDE.md` (ou `./CLAUDE.md` na raiz) — instructions, sempre carregada
- `~/.claude/projects/<projeto>/memory/MEMORY.md` — auto-memory primeira 200 linhas
- `~/.claude/projects/<projeto>/memory/<topico>.md` — carregado on-demand
- `autoMemoryEnabled: true` em settings.json (já é default)
- CLAUDE.local.md (opcional, gitignored, pessoal)

## Oportunidades emergentes (não obrigatórias)

1. **Plan Mode** (Jan 2026) — `/plan` ou Shift+Tab×2; read-only design-first; pode economizar 50-70% tokens em large tasks.
2. **Agent Teams** (Fev 2026, experimental, **já habilitado pela usuária**) — múltiplas sessões coordenadas; útil para research paralela e multi-angle review. Documentar quando usar.
3. **Custom MCP servers** (Bloco D+) — Puppeteer MCP para scraping; Postgres MCP se DB.
4. **Subagent per-agent memory** — se criar muitos agents.
5. **Path-scoped loading** — adotar amplamente.
