# Rodada 1 — Agent 1.3 — Lente das Lacunas

> Output do agent que leu integralmente os 11 arquivos de `.claude/rules/`, o CLAUDE.md, o plano e a memória do projeto, com o objetivo de identificar tudo o que **falta** nas regras existentes para o projeto-alvo (site web interativo + captura integral + Drive compartilhado).

## Lacunas vs. regras existentes — qual cobre parcialmente?

- Lacuna #4 (Proteção .xlsx) ↔ `protect-originals.md` cobre **proteção de arquivos de pesquisa Transcritorio**, não derivados em `data/derived/`. Não menciona `.xlsx` nem lock files. **Adaptar.**
- Lacuna #10 (Paths Unicode) ↔ `testing-protocol.md` menciona `pathlib` em Python, **mas não cobre bash, git, permissões**, nem testa com acentos/cedilha reais. **Expandir.**
- Lacuna #20 (ADR) ↔ `plan-first-workflow.md` documenta planos (COMO). **Falta registrar POR QUÊ** decisões arquitetônicas (stack, hosting, i18n). **Criar nova.**
- Lacuna #21 (Memória) ↔ `session-recovery.md` menciona MEMORY.md. **Falta padrão O QUÊ/QUANDO/COMO** registrar. **Criar template.**
- Lacuna #22 (Pipeline reproduzível) ↔ `minimal-changes.md` + `test-first-protocol.md` cobrem testes, **não automação de pipeline**. **Criar nova.**
- Lacuna #23 (Testes pipeline) ↔ `testing-protocol.md` cobre toy/unit; **não menciona testes de ETL** (planilha→JSON) nem helpers específicos de política. **Criar skill nova.**
- Demais 22 lacunas: **completam lacuna nova**, sem cobertura nas regras existentes.
