### A.1 — `normalize-categorico`

**Propósito:** Mapear valores ortográficos variantes (gráficos, hífens, aspas, capitalização) para vocabulário canônico em 7 campos críticos (Esfera formulação, Esfera execução, Tipo oferta, etc.).

**Frontmatter:**
```yaml
---
name: normalize-categorico
description: "Normaliza variantes ortográficas de campos categóricos para vocabulário canônico"
argument-hint: "[campo] [valor_bruto] [--verbose]"
allowed-tools: ["Read", "Grep"]
model: haiku
---
```

**Quando invocado:**
- Usuária: `/<nome> Esfera execução "Município - com parcerias"`
- Ou chamado internamente por `validar-dados-politicas` ou CLI pipeline

**Inputs esperados:**
- `campo`: string — um de {`Esfera de formulação`, `Esfera de execução`, `Tipo de oferta`, `Modalidade da oferta`, `Arranjo logístico-territorial`, `Abrangência territorial`, `Situação atual`}
- `valor_bruto`: string — valor vindo da planilha (p.ex. `"Municípios – com parcerias"`, `"municipal / com apoios`)
- `--verbose` (opcional): retorna também dicionário de mapeamento usado

**Outputs produzidos:**
- String normalizada (p.ex. `"Municipal - com parcerias"`)
- Ou `null` se valor não reconhecível (retorna erro + sugestão 3 valores mais próximos por edit distance)
- Mensagem ao usuário: `✓ normalizado para "X"` ou `⚠ valor ambíguo; candidatos: Y, Z, W`

**Algoritmo (9 passos):**

1. Ler file `data/vocabularios/canonico.json` com estrutura:
   ```json
   {
     "Esfera de execução": {
       "canonical_values": ["Federal", "Estadual", "Municipal", ...],
       "variants": {
         "federal": "Federal",
         "federação": "Federal",
         "Federação": "Federal",
         "fed.": "Federal",
         "municipios": "Municipal",
         "município": "Municipal",
         "municipal–com apoios": "Municipal - com parcerias",
         ...
       }
     },
     ...
   }
   ```

2. Validar que `campo` está em chaves do JSON; se não, retornar erro + lista de campos válidos

3. Extrair `variants` do campo

4. **Limpeza pré-lookup:** aplicar normalizações cosmética uniformes:
   - Remover espaços desnecessários (trim + collapse `\s{2,}`)
   - Converter para lowercase para lookup
   - Unificar hífens: `[–—]` → `-`
   - Unificar aspas: `[""'']` → `"`
   - Remover dois-pontos duplos `::` → `:`

5. Fazer lookup direto em `variants[valor_normalizado_lowercase]`

6. Se encontrado, retornar canonical value correspondente

7. Se não encontrado, calcular edit distance de `valor_normalizado` contra todas as chaves de `variants`; se max ≤ 2, retornar sugestão `"Achei algo próximo: X (distância 2)"` + valor canonical; se max > 2, retornar `null`

8. Se `--verbose`, também retornar:
   ```json
   {
     "resultado": "Estadual",
     "mapeamento_usado": "estado → Estadual",
     "field": "Esfera de execução",
     "confidence": 1.0
   }
   ```

9. Logar na auditoria (`data/logs/normalize-categorico_YYYY-MM-DD.log`) cada chamada com timestamp + campo + input + output + método (direto/sugestão/erro)

**Casos de erro:**
- Campo inválido → erro claro `"Campo X não reconhecido. Válidos: [lista]"`
- Valor 100% desconhecido (edit distance > 2) → aviso `"Não consegui normalizar valor 'ABC'. Verificar se é variante não catalogada?"` + sugerir registrar em `decisions/novo-mapeamento.md`
- JSON corrompido → fallback para versão cached em `.claude/cache/canonico_backup.json`

**Dependências externas:**
- `data/vocabularios/canonico.json` (criado na Rodada C como parte da exploração dos dados) — **não precisa de pacote Python além de json nativo**
- `pathlib` (Python stdlib)
- `difflib` (Python stdlib, para edit distance)

**Testes esperados:**

1. **Teste 1 — Mapeamento direto:** input `"Esfera de execução" "municipios"` → output `"Municipal"` (sim, sem capitalização)

2. **Teste 2 — Variante ortográfica:** input `"Esfera de execução" "Município - com parcerias"` → output `"Municipal - com parcerias"` (normaliza hífen mas mantém "com parcerias")

3. **Teste 3 — Sugestão aproximada:** input `"Esfera de execução" "Municpiaios"` (typo) → sugestão `"Municipal?"` com confidence 0.8

4. **Teste 4 — Campo inválido:** input `"Campo Inexistente" "valor"` → erro `"Campo inválido"`

5. **Teste 5 — Acentos/cedilha:** input `"Arranjo logístico-territorial" "Presencial em espaço físico"` → detectar e normalizar corretamente

**Risco de uso indevido:**
- Se vocabulário canônico estiver desatualizado, erros silenciosos em novo lote de fichas
- **Mitigar:** validar vocabulário contra planilha nova cada onda; adicionar feedback loop `"novos valores detectados na onda N"` em relatório

**Prioridade:** P1 (imediato — é blocador para qualquer agregação de dados)

### A.2 — `capturar-norma`

**Propósito:** Scraping responsável (robots.txt-aware, rate-limited) de leis/decretos/portarias de URLs em fichas. Armazenar snapshot (HTML/PDF/DOC) com metadados (URL, hash, data, licença, atribuição).

**Frontmatter:**
```yaml
---
name: capturar-norma
description: "Captura conteúdo integral de lei/decreto com metadata (robots.txt-aware, rate-limited)"
argument-hint: "[url_ficha_id] [--reCapturar] [--timeout-sec 30] [--formato html|pdf|doc|auto]"
allowed-tools: ["WebFetch", "Bash", "Read", "Write"]
model: opus
---
```

**Quando invocado:**
- Usuária (rara): `/<nome> federal:1 --reCapturar` (re-baixa se link mudou)
- Ou internamente pelo pipeline: `rodar-pipeline capturar --desde-ficha 100`

**Inputs esperados:**
- `url_ficha_id`: string — identificador global da ficha (`federal:1`, `sp:42`, etc.) ou URL direta
- `--reCapturar`: flag — força re-captura mesmo se snapshot recente existe
- `--timeout-sec`: int (default 30) — timeout HTTP em segundos
- `--formato`: {`html`, `pdf`, `doc`, `auto`} — formato preferido (auto tenta múltiplos)

**Outputs produzidos:**
- Arquivo snapshot: `data/external_snapshots/{hash_sha256}.html` (ou `.pdf` / `.doc`)
- Arquivo metadata: `data/external_snapshots/{hash_sha256}.meta.json`
- Retorno ao usuário: `✓ capturado {url}, hash={hash_curto}, {tamanho}KB, licenca=dominio-publico`
- Ou aviso: `⚠ 404 em {url} (último snapshot: {data})`

**Algoritmo (15 passos):**

1. Receber `url_ficha_id`; se for ID (tipo `federal:1`), resolver contra `data/derived/politicas.json` para extrair URL; caso contrário, usar URL diretamente

2. **Verificar cache local:**
   - Buscar em `data/external_snapshots/*.meta.json` com campo `url_original == url_entrada`
   - Se encontrado com `data_captura >= today - 30 dias` e não `--reCapturar`, retornar caminho do snapshot existente + metadata

3. **Validar robots.txt:**
   - Extrair domínio de URL (p.ex. `planalto.gov.br`)
   - GET `/robots.txt` do domínio; fazer parse
   - Se user-agent do projeto (identificado como `Bot-CatalogoPoliticas/1.0`) está em `Disallow`, registrar em log mas **continuar** (regra não é bloqueador legal, só etiqueta)
   - Se `Crawl-delay` ou `Request-rate` existem, respectar na próxima requisição

4. **Rate limiting por domínio:**
   - Manter `.claude/cache/rate_limit_tracker.json` com últimas N requisições por domínio
   - Intervalo mínimo: 1 segundo entre requisições do mesmo domínio
   - Se intervalo não respeitado, aguardar (com log informativo)

5. **HTTP HEAD request:**
   - Enviar HEAD para verificar status + content-type antes de GET
   - Se status != 200 (404, 403, timeout, etc.), registrar em `data/logs/captura_falhas.json` e retornar aviso ao usuário; **não tentar GET**

6. **GET conteúdo:**
   - User-Agent: `Mozilla/5.0 (Bot-CatalogoPoliticas/1.0; +http://projeto-url)`
   - Timeout: `--timeout-sec` (default 30s)
   - Follow redirects até 5 hops; registrar redirect chain em metadata

7. **Detectar content-type e parsing:**
   - Se `text/html`, armazenar como-é (ou minified HTML se >5MB)
   - Se `application/pdf`, tentar extrair texto via `PyPDF2` (fallback para armazenar PDF bruto)
   - Se `application/msword` ou `application/vnd.openxml...`, usar `python-docx` para extrair texto
   - Se content-type desconhecido, tentar `beautifulsoup4` como fallback HTML

8. **Validar conteúdo extraído:**
   - Conferir que resultado ≥ 100 caracteres (documento não está vazio)
   - Se < 100 chars, avisar `"Documento parece vazio ou parsing falhou"` + armazenar original bruto anyway

9. **Calcular hash SHA256 do conteúdo extraído**

10. **Escrever snapshot:**
    - Diretório: `data/external_snapshots/` (criar se não existir)
    - Nome: `{hash_sha256_primeiros_16_chars}.{extensao}`

11. **Escrever metadata JSON:**
    ```json
    {
      "snapshot_hash": "a1b2c3d4e5f6g7h8",
      "url_original": "https://...",
      "url_canonizada": "https://... (após redirects)",
      "data_captura": "2026-05-01T14:30:00Z",
      "status_http": 200,
      "content_type": "text/html; charset=utf-8",
      "tamanho_bytes": 125000,
      "tempo_captura_ms": 2500,
      "redirect_chain": ["https://a", "https://b"],
      "licenca_identificada": "dominio-publico (art. 8 Lei 9.610)",
      "atribuicao": "Governo Federal - Subchefia de Assuntos Jurídicos",
      "proximo_recheck": "2026-06-01T00:00:00Z",
      "formato_original": "html",
      "encoding": "utf-8",
      "robots_txt_complied": true,
      "parseable": true,
      "extraction_method": "beautifulsoup4 + html2text"
    }
    ```

12. **Registrar auditoria:**
    - Logar em `data/logs/captura_sucesso_YYYY-MM-DD.jsonl` (uma linha por captura)
    - Formato: timestamp, url, hash, tamanho, tempo_ms, licenca

13. **Tratar erros específicos:**
    - **Timeout (>timeout-sec):** log, não retry (servidor lento demais)
    - **404/403:** log, marcar URL como "quebrada" em `data/external_snapshots/urls_invalidas.json`
    - **SSL/TLS error:** log, tentar fallback HTTP se HTTPS falhou
    - **Encoding issues:** tentar `utf-8`, fallback `latin-1`, fallback `iso-8859-1`

14. **Respeitar LGPD/atribuição:**
    - Detectar se documento menciona restrições (copyright, termos de uso)
    - Para leis/decretos federais, pré-preenchido como domínio público
    - Armazenar campo `restricoes_identificadas` se houver

15. **Retornar feedback:**
    ```
    ✓ Capturado {ficha_id}: {url}
    • Hash: {hash_curto}
    • Tamanho: {size}KB, tempo: {ms}ms
    • Licença: {licenca}
    • Próx. recheck: {data}
    ```

**Casos de erro:**
- **URL inválida:** retornar erro de validação URL + sugerir correção
- **Servidor demorado (timeout):** log e não-bloqueador (marcar para recheck posterior)
- **Link 404 permítente:** marcar em `urls_invalidas.json` + avisar ao usuário
- **Arquivo gigante (>100MB):** avisar, descartar (log manualmente)
- **Encoding indetectável:** usar `chardet` para adivinhar, fallback latin-1

**Dependências externas:**
- `requests` ou `httpx` — HTTP client
- `beautifulsoup4` — HTML parsing
- `pypdf` ou `PyPDF2` — PDF text extraction
- `python-docx` — DOCX parsing
- `chardet` — encoding detection
- `pathlib` (stdlib)
- `hashlib` (stdlib)
- `json` (stdlib)

**Testes esperados:**

1. **Teste 1 — Captura HTML bem-sucedida:** URL → documento HTML capturado, metadata criada, hash gerado

2. **Teste 2 — Robots.txt respeitado:** requisição a domínio com `Disallow` → logar aviso mas continuar captura

3. **Teste 3 — Cache local reutilizado:** chamar 2× mesma URL com <30 dias → 2ª chamada retorna cache sem HTTP

4. **Teste 4 — Rate limit enforced:** 2 URLs mesmo domínio 100ms apart → aplicar delay

5. **Teste 5 — Erro 404:** URL quebrada → registrar em `urls_invalidas.json`, avisar, continuar pipeline

**Risco de uso indevido:**
- IP ban por scraping agressivo → **mitigar:** rate limit 1req/s/domínio, user-agent claro, respeitar robots.txt
- Armazenar conteúdo copyrighted → **mitigar:** assumir domínio-público para leis federais; avisar se conteúdo menciona restrições
- Memory leak com arquivos grandes → **mitigar:** limite 100MB/arquivo

**Prioridade:** P1 (imediato — valor alto, Bloco D depende inteiramente disso)

### A.3 — `extrair-texto-documento`

**Propósito:** Parse de múltiplos formatos (HTML, PDF, DOCX, ODT) com fallback de encoding. Extrai texto estruturado.

**Frontmatter:**
```yaml
---
name: extrair-texto-documento
description: "Extrai texto de documento (HTML/PDF/DOCX/ODT) com fallback encoding"
argument-hint: "[arquivo_local] [--formato auto|html|pdf|docx|odt] [--idioma pt|en] [--max-palavras 50000]"
allowed-tools: ["Read", "Bash"]
model: haiku
---
```

**Quando invocado:**
- Usuária (rara): `/<nome> ~/downloads/decreto_123.pdf`
- Internamente: por `capturar-norma` após baixar snapshot

**Inputs esperados:**
- `arquivo_local`: path absoluto a documento local
- `--formato`: `auto` (detecta por ext/mime) | `html` | `pdf` | `docx` | `odt`
- `--idioma`: `pt` (padrão) | `en` — informação para OCR se PDF image-based
- `--max-palavras`: int (default 50000) — truncar se documento > limite

**Outputs produzidos:**
- String com texto extraído (UTF-8)
- Ou JSON estruturado (opcional): `{"tipo": "decreto", "numero": "123.456", "data": "2020-01-01", "corpo": "...", "assinantes": [...]}`
- Metadata: `{"formato_original": "pdf", "encoding_detectado": "utf-8", "palavras": 4250, "sucesso": true}`

**Algoritmo (10 passos):**

1. Validar caminho; conferir que arquivo existe

2. Se `--formato auto`, detectar:
   - Por extensão: `.pdf` → PDF, `.docx` → DOCX, `.odt` → ODT, `.html` / `.htm` → HTML, `.txt` → text
   - Se extensão não clássica, ler primeiros 100 bytes + `python-magic` (libmagic) para detectar mime type

3. **Parsing HTML:**
   ```python
   from bs4 import BeautifulSoup
   soup = BeautifulSoup(open(arquivo, 'r', encoding='utf-8').read(), 'html.parser')
   # Remover script/style tags
   for tag in soup(['script', 'style']):
       tag.decompose()
   # Extrair texto + linhas vazias
   texto = soup.get_text(separator='\n', strip=True)
   ```

4. **Parsing PDF:**
   ```python
   import pypdf
   reader = pypdf.PdfReader(arquivo)
   texto = '\n'.join(page.extract_text() for page in reader.pages)
   # Se extract_text() retorna vazio (PDF image-based), tentar OCR com pytesseract
   ```

5. **Parsing DOCX:**
   ```python
   from docx import Document
   doc = Document(arquivo)
   texto = '\n'.join(p.text for p in doc.paragraphs)
   # Adicionar textos de tabelas se presentes
   ```

6. **Parsing ODT:**
   - Usar library `odfpy` (odf) ou extrair ZIP + ler `content.xml`
   ```python
   from odf import text as odf_text
   from odf.opendocument import load
   doc = load(arquivo)
   # Extrair body text
   ```

7. **Tratamento de encoding:**
   - Tentar UTF-8 primeiro
   - Se falhar, usar `chardet.detect(raw_bytes)` para adivinhar
   - Fallback: latin-1 (nunca falha, pode ter garbage)
   - Logar encoding detectado em metadata

8. **Limpeza de whitespace:**
   ```python
   # Colapsar múltiplas linhas em branco
   texto = '\n'.join(line.strip() for line in texto.split('\n') if line.strip())
   ```

9. **Validação:**
   - Conferir texto final ≥ 100 caracteres (não vazio)
   - Contar palavras (split por whitespace)
   - Se > `--max-palavras`, truncar + aviso `"Documento muito grande; truncado a N primeiras palavras"`

10. **Retornar:**
    ```json
    {
      "texto": "conteúdo...",
      "metadata": {
        "formato": "pdf",
        "encoding": "utf-8",
        "palavras": 4250,
        "caracteres": 28000,
        "sucesso": true
      }
    }
    ```

**Casos de erro:**
- Arquivo não existe → erro claro
- Formato desconhecido → tentar auto-detect via magic; se falhar, erro
- PDF image-based (OCR needed) → log aviso, retornar texto vazio + flag `"ocr_needed": true`
- DOCX/ODT corrompidos → tentar fallback ZIP extract
- Encoding indetectável → usar latin-1 + avisar `"encoding-fallback"`

**Dependências externas:**
- `beautifulsoup4` — HTML
- `pypdf` — PDF
- `python-docx` — DOCX
- `odfpy` — ODT
- `chardet` — encoding detection
- `python-magic` (optional, para auto-detect mime)
- `pytesseract` (optional, para OCR de PDFs image-based)

**Testes esperados:**

1. Teste 1 — HTML com encoding UTF-8 → extrai texto limpo
2. Teste 2 — PDF text-based → extrai conteúdo
3. Teste 3 — DOCX com tabelas → extrai texto + nomes de tabelas
4. Teste 4 — Arquivo encoding latin-1 → detecta fallback, extrai, avisa
5. Teste 5 — Documento > max-palavras → trunca + aviso

**Risco:** OCR lento (Tesseract), memory em PDFs gigantes. Mitigar com timeout, limite de tamanho.

**Prioridade:** P1 (blocador para Bloco D)

### A.4 — `rodar-pipeline`

```yaml
---

allowed-tools: ["Bash", "Read", "Write", "Glob"]
model: opus
---
```

**Quando invocado:**
- Usuária: `/<nome> tudo` (executa pipeline completo)
- Ou: `/<nome> validate --onda 1` (valida onda 1)
- Ou internamente no CI/CD

**Inputs esperados:**
- `etapa`: {`load`, `normalize`, `dedupe`, `validate`, `build-json`, `testar`, `tudo`}
- `--desde-etapa`: skip etapas anteriores (ex.: `--desde-etapa dedupe`)
- `--planilha`: path da planilha (default: `Fichas das Políticas - 1ª onda.xlsx`)
- `--onda`: número da onda para nomeação de outputs (default: 1)

**Outputs produzidos:**
- Console log real-time de cada etapa
- Arquivo `data/derived/pipeline_onda{N}_YYYY-MM-DD_HHmmss.log`
- JSONs em `data/derived/onda{N}/`
- Relatório sumário: `data/derived/onda{N}_report.json`

**Algoritmo (10 passos altos — detalhes em justfile):**

1. **Validar précondições:**
   - Arquivo planilha existe + não está aberto (verificar lock file `~$...`)
   - Diretório `data/derived/` existe
   - Python ≥3.9 disponível

2. **Etapa load:** ler `.xlsx` com `openpyxl(read_only=True)` → output intermediário `data/derived/_temp/onda1_raw.json`

3. **Etapa normalize:** aplicar `normalize-categorico` a cada célula em 7 campos críticos → `_temp/onda1_normalized.json`

4. **Etapa dedupe:** aplicar `deduplicacao.md` logic → detectar federais replicadas, marcar com `is_federal_replica` → `_temp/onda1_deduped.json`

5. **Etapa validate:** validar cada ficha contra schema em `data/schema/politicas-schema.json` → relatório `_temp/onda1_validation_report.json`; **falhar se erros críticos**

6. **Etapa build-json:** transformar para formato canônico (nomes de chaves normalizados, arrays estruturados) → `data/derived/onda1/politicas_completo.json` + `onda1/politicas_por_uf.json` (nested by UF)

7. **Etapa testar:** executar `testar-pipeline` com subset (10 fichas) como sanity check

8. **Sumário:** gerar `data/derived/onda1_report.json`:
   ```json
   {
     "onda": 1,
     "data": "2026-05-01",
     "politicas_total": 439,
     "por_uf": {"SP": 53, "RJ": 41, ...},
     "federais_unicas": 33,
     "federais_replicadas": 33 * 8,
     "validacao_status": "OK",
     "erros_encontrados": 3,
     "avisos": ["RJ tem 2 duplicatas", ...],
     "tempo_total_ms": 5000
   }
   ```

9. **Tratamento de erro:** se uma etapa falha:
   - Log completo do erro
   - Sugerir próximos passos (ex.: `"Erro na normalização. Verificar mapeamento em normalize-categorico --verbose"`)
   - Permitir resume com `--desde-etapa`

10. **Cleanup:** remover arquivos `_temp/` se sucesso; preservar se falha (para debug)

**Casos de erro:**
- Lock file presente → erro "Planilha aberta no Excel"; usuária fecha e retenta
- Schema inválido → erro clara: `"Campo X em ficha federal:5 violou constraint Y"`
- Encoding corrupto → tentar fallback
- Dedupe ambígua → avisar (federais:2 com exatamente mesmo ID?)

**Dependências externas:**
- `openpyxl` — leitura Excel
- `jsonschema` — validação schema
- `pandas` (opcional, para operações bulk)
- `just` ou `make` — orquestração (justfile no raiz do projeto)

**Testes esperados:**

1. Teste 1 — Pipeline completo com onda 1 (subset 10 fichas) → sucesso, JSONs gerados
2. Teste 2 — Resume de etapa com `--desde-etapa dedupe` → pula load/normalize
3. Teste 3 — Erro em validação → pipeline falha com mensagem clara, preserva _temp
4. Teste 4 — Planilha locked → erro e instrução ao usuário
5. Teste 5 — Onda 2 (novo arquivo) → detecta, renomeia outputs, sucesso

**Risco:** pipeline quebrado em onda nova. Mitigar com testes extensos em Bloco C, separação de dados temporários.

**Prioridade:** P1 (imediato — orquestra todo o restante)

### A.6 — `validar-link`

**Propósito:** HEAD request responsável em ~412 links de fichas. Classificar 200/301/404/timeout. Relatório de links quebrados.

**Frontmatter:**
```yaml
---
name: validar-link
description: "Valida ~412 links (HEAD request) e classifica por status; relatório de risco"
argument-hint: "[--onda numero] [--timeout-sec 10] [--retry 2] [--salvar-relatorio]"
allowed-tools: ["Bash", "Read", "Write"]
model: haiku
---
```

**Quando invocado:**
- Internamente por pipeline ou scheduler (semanal)
- Usuária (raramente): `/<nome> --onda 1 --salvar-relatorio`

**Inputs esperados:**
- `--onda`: número da onda (default: onda atual)
- `--timeout-sec`: timeout por link (default 10)
- `--retry`: retry count em falha (default 2)
- `--salvar-relatorio`: escrever `data/reports/validacao_links_YYYY-MM-DD.json`

**Outputs produzidos:**
- Relatório: `data/reports/validacao_links_{data}.json` (se `--salvar-relatorio`)
- Ou JSON via stdout (sem salvar)
- Exemplo saída:
  ```json
  {
    "data": "2026-05-01",
    "onda": 1,
    "total_links": 412,
    "status_200": 395,
    "status_301_redirect": 12,
    "status_404": 3,
    "timeout": 2,
    "links_quebrados": [
      {
        "url": "http://...",
        "status": 404,
        "ficha_id": "ce:45",
        "ficha_nome": "PRONATEC"
      },
      ...
    ],
    "risco_nivel": "BAIXO"
  }
  ```

**Algoritmo (9 passos):**

1. **Load fichas** da onda (JSON canônico)

2. **Extrair URLs** de campo `Link` + `Base legal` (pode ter URLs múltiplas separadas por `;`)

3. **Deduplicar URLs** (contar quantas fichas referenciam cada)

4. **Rate limit:** respeitar `robots.txt` + 1 req/s/domínio

5. **Para cada URL:**
   - HEAD request com timeout `--timeout-sec`
   - Capturar `status_code` + `Location` (se redirect)
   - Se timeout ou erro DNS: retry até `--retry`
   - Se ainda falhar: marcar como timeout

6. **Classificar resultado:**
   - 200/20x → OK
   - 301/302 → Redirect (seguir, conferir destino é válido)
   - 404 → Quebrado
   - 403 → Acesso negado (OK, provavelmente servidor respeitoso)
   - 5xx → Servidor error (aviso, talvez temporário)
   - Timeout/DNS error → Quebrado

7. **Logar**: escrever em `data/logs/validacao_links_YYYY-MM-DD.jsonl` (streaming, linha por linha)

8. **Calcular risco:**
   - CRÍTICO: >20% links quebrados
   - MÉDIO: 5-20% quebrados
   - BAIXO: <5% quebrados

9. **Retornar relatório** + nível de risco

**Casos de erro:**
- JSON fichas inválido → erro
- Rate limit violated → backoff + log

**Dependências externas:**
- `requests` ou `httpx`
- `json` (stdlib)

**Testes esperados:**

1. Teste 1 — 10 URLs mix (OK/redirect/404) → classifica corretamente
2. Teste 2 — Timeout → retried e marcado
3. Teste 3 — Relatório gerado → risco calculado

**Prioridade:** P1 (importante para monitoramento, Bloco D/G)

### C.3 — PostToolUse — Valida JSON contra schema (opcional)

**Evento:** PostToolUse

**Pseudocódigo:**
```python
def hook_validate_json_schema(event: dict) -> int:
    file_path = event['file_path']
    
    if file_path.endswith('.json'):
        with open(file_path) as f:
            data = json.load(f)
        
        schema_path = 'data/schema/politicas-schema.json'
        with open(schema_path) as f:
            schema = json.load(f)
        
        validator = jsonschema.Draft7Validator(schema)
        errors = list(validator.iter_errors(data))
        
        if errors:
            print(f"JSON INVÁLIDO: {len(errors)} violações de schema")
            for e in errors[:5]:
                print(f"  - {e.message} em {e.json_path}")
            return 1  # Bloqueia
    
    return 0
```

## PARTE G — ORDEM DE IMPLEMENTAÇÃO

**Sequência justificada (7 fases):**

### Fase 1 — Proteção + Validação (hooks + schema) — 3-5 dias
**Porquê primeiro:** sem proteção, risco de corromper fonte; sem schema, JSONs inválidos propagam.

1. **C.1 Hook:** bloqueia escrita em `.xlsx` → ganho imediato em segurança
2. **C.2 Hook:** avisa lock file → reduz incoerências
3. **Schema JSON:** criar `data/schema/politicas-schema.json` com todos os campos e constraints
4. **C.3 Hook:** validar JSON pós-escrita → qualidade

### Fase 2 — Vocabulário Canônico + Normalize (A.1) — 3-5 dias
**Porquê:** blocador para qualquer agregação de dados; E logo vira P1.

1. **Criar:** `data/vocabularios/canonico.json` com 7 campos + variantes (via exploração Bloco C)
2. **Implementar:** skill `normalize-categorico`
3. **Testar:** com 10 fichas subset

### Fase 3 — ETL Core (A.4 + A.5) — 7-10 dias
**Porquê:** orquestra tudo; cria data flow.

1. **Implementar:** `rodar-pipeline` skill (load → normalize → dedupe → validate → build-json)
2. **Implementar:** `testar-pipeline` skill
3. **Criar:** `justfile` ou `Makefile` central
4. **Testar:** pipeline completo com subset

### Fase 4 — Captura Externa (A.2 + A.3 + B.2) — 10-14 dias
**Porquê:** complexo; precisa de skills anteriores; valores altos; pronto para Bloco D em breve.

1. **Implementar:** `extrair-texto-documento` skill
2. **Implementar:** `capturar-norma` skill
3. **Implementar:** `web-scraper-respeitoso` agent (orquestra captura com logging)
4. **Testar:** com 5-10 links sample

### Fase 5 — Auditoria + Monitoramento (A.6 + A.7 + A.8 + B.1) — 5-7 dias
**Porquê:** complementa pipeline; detecta qualidade.

1. **Implementar:** `validar-link` skill
2. **Implementar:** `auditar-derivado` skill
3. **Implementar:** `data-auditor` agent
4. **Implementar:** `extrair-ficha` skill (helper)
5. **Testar:** auditoria full run

### Fase 6 — Documentação + Processo (B.4 + C.4 + C.5) — 3-5 dias
**Porquê:** overhead baixo; agrega valor em Rodadas futuras.

1. **Implementar:** `documentador-decisoes` agent
2. **Implementar:** hooks de auditoria (C.4, C.5)
3. **Criar:** `.claude/README.md` descrevendo artefatos
4. **Atualizar:** `MEMORY.md` template

### Fase 7 — Redação (B.3 + refinements) — 3-5 dias
**Porquê:** última; prepara UI/docs.

1. **Implementar:** `revisor-redacao-pt-br` agent
2. **Refinement:** testar todas as skills end-to-end
3. **Documentação:** criar guias de uso para cada skill

**Tempo total estimado:** 35-50 dias (com paralelização possível em some phases)
